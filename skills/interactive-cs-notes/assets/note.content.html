This note is a small interactive textbook for sorting, searching, traversal, and binary search trees. It is written for a CS2 reader who knows arrays and loops but wants the invariants to become obvious. The labs are not animations to watch; they are places to commit to a prediction, step the machine, and check the model.

By the end, you should be able to

  • State the invariant that makes each algorithm correct, not just its pseudocode.
  • Predict the next comparison, swap, dequeue, or tree edge before the lab shows it.
  • Explain why binary search is $O(\log n)$ and why an unbalanced BST is not.
  • Choose BFS or DFS from the shape of the problem, not from habit.
  • Recognise the input that turns a good average case into a bad worst case.

How to use this note

Each lab follows the same loop: predict → step → explain → transfer. The prediction prompt is deliberately before the controls. If you skip it, the lab becomes a video, and the evidence on algorithm visualisation is clear that passive viewing is the weak version.

Study protocol

Read the definition and the invariant first. Then close the explanation, answer the prediction, and step through the lab until you can narrate each transition without looking at the status line. Finish with the retrieval quiz and come back in one day, one week, and three weeks.

The one idea: invariants

An algorithm is not a list of lines; it is a maintained claim. A loop invariant is a statement that is true before the loop starts, stays true after every iteration, and — together with the exit condition — implies the result.

Definition · loop invariant

A property $P$ is a loop invariant for a loop if (1) $P$ holds before the first iteration, (2) if $P$ holds at the start of an iteration and the iteration terminates, then $P$ holds at the start of the next iteration, and (3) when the loop exits, $P$ plus the exit condition gives the postcondition.

For insertion sort, the invariant is: before iteration $i$, the prefix $A[0..i-1]$ is sorted and contains exactly the original first $i$ elements. The inner loop shifts larger elements right until the key can be inserted. The invariant explains both the correctness and the best case: if the array is already sorted, the inner loop stops immediately, so the total work is linear.

$$ T_{\text{insertion}}(n) = \sum_{i=1}^{n-1} \bigl(1 + \text{number of shifts at } i\bigr) \quad\Longrightarrow\quad T_{\text{best}} = \Theta(n),\qquad T_{\text{worst}} = \Theta(n^2). $$

Lab 01 · Sorting: watch the invariant

Bubble sort grows a sorted suffix; selection sort grows a sorted prefix by repeatedly taking the minimum; insertion sort grows a sorted prefix by inserting one key at a time. The bars are the same; the invariant is not.

Predict first: after one full bubble pass, which position is guaranteed?

The last position holds the largest element. Bubble sort compares adjacent pairs left to right, so the maximum “bubbles” all the way to the end in one pass. Nothing else is guaranteed yet.

    Common mistake

    “Selection sort is $O(n\log n)$ because it uses a minimum.” No: finding the minimum of an unsorted suffix is a linear scan, and it is repeated $n$ times. The absence of nested loops in the code is not the point; the total number of comparisons is.

    Lab 02 · Binary search: halve the uncertainty

    Binary search maintains one invariant: if the target is in the array, it is inside the current range $[low, high]$. Every comparison must discard a non-empty half. The moment the range is empty, the target is absent.

    Predict first: if A[mid] < target, which half can you discard?

    The left half, including mid. Because the array is sorted, every index at or below mid holds a value no larger than A[mid], so none of them can equal the target. The new range is [mid + 1, high].

      Why the bound is logarithmic

      After $k$ comparisons the range has size at most $\lceil n/2^k \rceil$. The search stops when the range is empty, which happens once $2^k > n$. Therefore $k = \Theta(\log n)$. The exact worst-case number of comparisons is $\lceil \log_2(n+1) \rceil$, not “exactly $\log_2 n$”.

      $$ n \to \frac{n}{2} \to \frac{n}{4} \to \cdots \to 1 \quad\Longrightarrow\quad k \le \lceil \log_2(n+1) \rceil. $$

      Two classic bugs

      Overflow: in a fixed-width language, (low + high) / 2 can overflow even when both indices fit. Use low + (high - low) / 2. Wrong update: setting low = mid instead of mid + 1 can loop forever when the range has two elements.

      Lab 03 · Graph traversal: the frontier is the algorithm

      BFS and DFS visit the same graph and can produce very different orders. The difference is not the graph; it is the frontier discipline. BFS takes the oldest discovered node (queue). DFS takes the newest (stack).

      Predict first: from A, which traversal reaches H first?

      BFS reaches H at depth 3 (A → B → D → H, or A → B → E → H). DFS can dive through B, D, H immediately, so it may reach H earlier in steps but along a deeper path. The right question is not “which is faster?” but “which order do I need?”.

      Lab 03 · Traversal

      The frontier is the algorithm

      BFS keeps a queue; DFS keeps a stack. The only difference is which end you take from.

        What each traversal is for

        BFS

        • Shortest path in an unweighted graph.
        • Level-order exploration.
        • Connected components with a queue.
        • “Nearest” anything: servers, moves, social distance.

        DFS

        • Cycle detection.
        • Topological sorting.
        • Backtracking and maze solving.
        • Exploring one branch deeply before siblings.

        Both are $O(V+E)$ with an adjacency list. The complexity is the same; the order and the memory profile are not. BFS’s frontier can be wide (up to $O(V)$); DFS’s stack can be deep (up to $O(V)$). A DFS order is also not unique: it depends on the adjacency order and on whether a node is marked when it is pushed or when it is popped. The lab uses mark-on-pop with an explicit stack, which is one valid DFS.

        Lab 04 · Binary search trees: order is the structure

        A binary search tree maintains the ordering invariant: for every node, all keys in its left subtree are smaller and all keys in its right subtree are larger. That invariant gives a sorted inorder traversal and a search that follows one root-to-leaf path.

        Predict first: where does 65 go in the default tree?

        Start at 50: 65 > 50, go right to 70. 65 < 70, go left to 60. 65 > 60, so it becomes the right child of 60. The comparison path is 50 → 70 → 60 → 65.

        The shape is the complexity

        A BST search does one comparison per level. If the tree is balanced, its height is $\Theta(\log n)$, so search is $O(\log n)$. If the tree degenerates into a chain — for example, inserting sorted keys — its height is $n-1$, so search is $O(n)$. The algorithm did not change; the input order did.

        Lab 05 · Growth rates: a shape, not a number

        Big-O is about the growth of work as $n$ grows, not about a stopwatch. The chart shows five functions on the same axes. Switch the y-axis between linear and logarithmic: the linear view shows why quadratic algorithms collapse; the log view keeps the small functions visible.

        Predict first: when $n$ doubles from 32 to 64, what happens to $n^2$?

        It quadruples: $32^2 = 1{,}024$ and $64^2 = 4{,}096$. Linear work doubles, $n\log n$ slightly more than doubles, and quadratic work quadruples. That difference in scaling is what Big-O names.

        Common mistake

        “$O(2n)$ is slower than $O(n)$.” Constants matter in practice, but Big-O deliberately hides them. $O(2n)$ and $O(n)$ are the same growth class. What matters is how the work scales when $n$ doubles: linear doubles, $n\log n$ slightly more than doubles, quadratic quadruples.

        Summary · one screen

        The five sentences to keep

        • Sorting: name the invariant (sorted prefix, sorted suffix, or “prefix is sorted and contains the first i keys”) before the code.
        • Binary search: sorted input + a range that always contains the answer + discard half. The bound is $\lceil \log_2(n+1) \rceil$.
        • BFS: queue, level order, shortest path in unweighted graphs, $O(V+E)$.
        • DFS: stack/recursion, depth first, cycles and topological order, $O(V+E)$.
        • BST: inorder is sorted; height is the complexity; sorted insertion degenerates to a chain.

        Exercises

        Exercise 1 · Trace

        Run insertion sort on [5, 2, 4, 6, 1, 3]. Write the array after each insertion of the key, and count comparisons and shifts. Then check your trace against the lab.

        Solution

        Start [5 | 2, 4, 6, 1, 3]. Insert 2: [2, 5 | 4, 6, 1, 3]. Insert 4: [2, 4, 5 | 6, 1, 3]. Insert 6: [2, 4, 5, 6 | 1, 3]. Insert 1: [1, 2, 4, 5, 6 | 3]. Insert 3: [1, 2, 3, 4, 5, 6]. Comparisons: 1 + 2 + 1 + 4 + 3 = 11; shifts: 1 + 2 + 0 + 4 + 3 = 10.

        Exercise 2 · Binary search bound

        Show that the worst-case number of comparisons for binary search on $n$ sorted elements is $\lceil \log_2(n+1) \rceil$. Start from the range size after $k$ comparisons.

        Solution

        After $k$ comparisons the range has size at most $\lceil n/2^k \rceil$. The search continues while the range is non-empty, so it stops when $2^k > n$. The smallest such $k$ is $\lfloor \log_2 n \rfloor + 1 = \lceil \log_2(n+1) \rceil$. For $n=1{,}024$, this is 11.

        Exercise 3 · BFS or DFS?

        For each task, choose BFS or DFS and justify it in one sentence: (a) shortest number of moves in a maze, (b) detect a cycle in a directed graph, (c) find the nearest server in an unweighted network, (d) enumerate all paths in a small graph.

        Solution

        (a) BFS: the first time you reach the exit, the path has the fewest edges. (b) DFS: a back edge to a node on the current recursion stack detects a cycle. (c) BFS: “nearest” is fewest edges. (d) DFS: backtracking naturally enumerates paths; BFS also works but stores many partial paths.

        Exercise 4 · Degenerate tree

        Insert $1,2,3,4,5,6,7$ into an empty BST. Draw the tree, give its height, and explain why the search for 7 is $O(n)$ even though the tree has only 7 nodes. What insertion order would give a balanced tree?

        Solution

        The tree is a right chain $1 \to 2 \to 3 \to 4 \to 5 \to 6 \to 7$; height is 7 (or 6 edges). Searching for 7 visits every node, so the cost is linear in $n$. A balanced order is $4,2,1,3,6,5,7$ (or any order that keeps the median at the root recursively).
